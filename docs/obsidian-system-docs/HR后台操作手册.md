# HR 后台操作手册

## 一、先建立岗位与 JD

新岗位不需要先准备岗位人才画像。正确顺序是“岗位 JD → 画像草稿 → 人工审核生效 → 候选人导入 → 面试排期”。

1. 进入“招聘任务后台”。
2. 点击“岗位与 JD”。
3. 点击“新建岗位”，填写岗位名称、可选岗位编号和完整 JD。
4. JD 可以粘贴，也可以上传 PDF、DOCX、TXT 或 Markdown 文件后核对提取内容。
5. 点击“保存 JD、理解岗位并生成画像草稿”。
6. 检查“系统对岗位的理解”：确认岗位使命、业务结果和三轮验证维度符合真实工作，不是对几个词的机械复述。
7. 检查“已排除非岗位因素”；性别、年龄、婚育、籍贯、特定学校等内容不得进入问题或画像。
8. 点击“查看画像草稿”，与业务负责人核对后再人工生效。
9. 返回岗位页面，点击“为该岗位导入候选人”。

已有岗位修改 JD 后，系统只刷新尚未开始的面试；进行中和已完成的面试保留当时使用的标准。暂停招聘的岗位不能继续导入候选人或安排新面试。

## 二、导入候选人

1. 进入“招聘任务后台”。
2. 选择“批量导入面试候选人”。
3. 选择已经在“岗位与 JD”中建档的岗位，上传简历。
4. 核对姓名、联系方式、工作年限、学历、当前公司和职位。
5. 确认后进入待排期列表。

这里导入的是已经通过筛选、确定参加面试的候选人，不在本系统内进行简历排序或淘汰。

## 三、配置岗位面试流程

不同岗位可以使用不同流程。业务面、HR 面、CEO 面可任选 1–3 轮，并可调整为任意实际顺序，例如“HR 面 → 业务面”“业务面”“业务面 → CEO 面”。

1. 勾选本岗位需要的轮次，至少保留一轮。
2. 使用“前移 / 后移”调整实际先后顺序。
3. 按顺序设置每轮面试官、时间和线下/飞书场景。
4. 提交前核对页面顶部的“当前流程”。

本次设置会记为该岗位的默认流程，下次安排同岗位候选人时自动带出；仍可按候选人实际情况调整。系统按分配关系决定面试官登录后看到谁、使用哪一轮体系。

## 四、过程跟进

- “今日行动中心”查看待排期、今日面试、待补评价、可终审和知识审批。
- 左侧主导航只保留首页、面试工作台、本轮评价和 HR 后台；岗位、简历和手动排期保留为高频入口，其余低频模块收进“更多后台功能”。
- 待补评价卡片直接展示 AI 参考分和建议。确认不需要继续占用待办时可点“移出待评价”；该操作不会删除录音、逐字稿、证据或评分草稿。
- “飞书通知中心”核对新排期、24 小时提醒、待补评价、终审和知识审批消息。
- “面试质量分析”观察统一题覆盖率、候选人表达占比、证据密度和异常信号。

## 五、岗位流程终审

1. 打开候选人的“岗位面试汇总”。
2. 先看“全部对话综合参考”：确认实际配置的各轮分别使用了本轮专属评价维度，并核对各轮逐字稿段数、证据数与有证据维度数。
3. 综合参考分先按各轮全部真实问答独立评分，再对有证据的轮次等权汇总；它不要求面试官照题库提问，也不能替代人工决定。
4. 核对所有已配置轮次的完成情况、人工评价、能力评分、分歧与待验证问题。
5. 生成报告草稿并核对管理层摘要与 HR 完整档案。
6. 必要时锁定报告版本。
7. 勾选人工确认，决定进入录用审批、补充面试、暂缓或关闭流程。

## 六、知识与画像

- 人才知识库：审批脱敏知识提案，批准后才发布到 Obsidian。
- 公司基础人才画像：编辑公司通用能力、证据、风险、统一问题、评分锚点和主验证轮次；保存草稿后由 HR 二次确认生效。
- 岗位人才画像：继承当前公司基础画像，再结合 JD 与岗位样本生成草稿，核对后人工生效。
- 北森历史样本：先脱敏预览，再导入结构化招聘结果和能力信号。
- 系统文档：核对同步状态，人工确认后同步本目录文档。

## 七、数据治理

在“数据治理与审计”查看到期与临期材料。清理前必须核对候选人和期限，并勾选人工确认。清理原始敏感材料后，能力评分、人工评价、最终决定和审计记录继续保留。

## 八、试点就绪检查

- HR 可以查看身份、语音、模型、数据库、存储、HTTPS 和知识库的当前状态。
- “试点阻断项”需要在真实候选人试点前完成；“上线调整项”不影响本地演示，但不能直接带入生产。
- 内网穿透或免费临时域名可以用于无真实候选人资料的短期演示；正式试点仍需服务器、正式域名、HTTPS、访问控制、持久化存储和备份。
- 只有管理员可以运行连接测试；HR 不接触服务器密钥。
- 腾讯云 ASR 显示配置完整后，仍需由管理员组织短音频验收。
- 北森权限当前属于可滞后项，不阻塞首轮试点。
