# Interview Copilot 产品说明

## 产品定位

Interview Copilot 是为企业人工面试官提供面试前、面试中和面试后辅助的 AI 面试副驾驶。

它帮助面试官围绕岗位要求和候选人的真实经历提出问题，在面试过程中形成实时字幕、提示值得继续核实的证据缺口，并在面试结束后生成可追溯的评价草稿。AI 提供的是证据、问题和建议，最终判断始终由面试官或 HR 作出。

它不是：

- 自动招聘或自动淘汰系统；
- 自动变更候选人阶段的决策系统；
- 替代业务面试官、HR 或管理者的机器人；
- 根据表情、眼神、口音、语速、停顿或紧张程度进行“测谎”的工具。

## 核心用户

### HR

- 建立岗位、导入 JD 和维护岗位人才画像；
- 批量导入已经进入面试环节的候选人；
- 为岗位选择 1–3 个面试轮次、调整顺序并分配面试官；
- 查看行动中心、跨轮汇总、报告、数据治理和知识审批；
- 对候选人阶段变化和知识发布作最终人工确认。

### 业务面试官

- 查看分配给自己的面试；
- 阅读候选人简历、岗位要求和前轮允许带入的信息；
- 使用统一题、简历与 JD 结合题，以及实时追问建议；
- 核对证据并提交本轮人工评价。

### HR 面试官

- 核实动机、价值观、工作方式和岗位相关风险；
- 读取前轮已确认信息，但不直接继承前轮录用结论；
- 提交本轮评价并补充下一轮需要验证的问题。

### CEO / 高管面试官

- 根据岗位实际需要参与流程；
- 聚焦岗位关键判断、责任边界和公司阶段适配；
- 读取前轮已确认事实和待验证事项。

### 管理员

- 配置身份、模型、ASR、通知、数据库、存储与知识库；
- 执行安全的连通性检查；
- 查看系统就绪状态和审计结果。

## 当前真实流程

```text
岗位建立与 JD 导入
        ↓
公司基础画像 + 岗位人才画像草稿
        ↓
HR / 业务人工确认生效
        ↓
导入已通过筛选的候选人
        ↓
选择 1–3 个面试轮次、排序、排期和分配面试官
        ↓
面试前读取简历、JD、题目和前轮确认信息
        ↓
面试官确认录音与 AI 分析告知
        ↓
实时收音 → 字幕 → 话者判断 → 证据与追问建议
        ↓
结束面试 → AI 证据评分与评价草稿
        ↓
面试官核对证据并提交人工评价
        ↓
满足该岗位已配置轮次后进入 HR 终审
        ↓
HR 人工确认候选人阶段和报告
        ↓
脱敏知识提案 → HR 审批 → Obsidian 发布
```

候选人的前置筛选不属于本项目。未来由 `boss-recruiting-agent` 通过版本化契约向本项目提供筛选结果，但当前没有在线系统间调用。

## 两种面试模式

### 结构化模式

- 每轮保留少量统一必问题；
- 根据 JD 与简历中可核实的经历生成定制题；
- 记录题目覆盖情况；
- 漏问只影响面试完整度，不直接成为候选人的负面证据。

### 自由对话分析模式

- 不要求面试官按预设题目提问；
- 系统分析整场面试官与候选人的实际对话；
- 临场问题与预设问题具有同等证据资格；
- 面试结束后仍生成有证据约束的参考评分和下一轮建议。

## 核心产品原则

1. **证据优先**：能力判断必须尽可能绑定逐字稿中的候选人原话。
2. **未知不是负面**：没有问到、没有回答或 ASR 无法确认，只能形成信息缺口。
3. **人工确认优先**：AI 不自动录用、淘汰、变更阶段或发布知识。
4. **按轮次分工**：业务、HR 和 CEO 面使用不同证据范围；实际顺序和组合由岗位决定。
5. **避免过拟合**：单场面试发现的问题先记录和积累样本，明确 Bug、安全或数据问题除外。
6. **数据最小化**：外部模型只接收完成任务所需的上下文；候选人数据不进入 GitHub 或系统运维知识库。
7. **禁止行为学测谎**：非语言表现不能直接产生诚信、能力或录用判断。

## 已实现与边界

| 能力 | 当前状态 | 边界 |
|---|---|---|
| 浏览器面试工作台 | 已实现 | 当前是原生 HTML/CSS/JavaScript 单页应用 |
| 飞书身份 | 已实现 OAuth 与角色映射 | 未实现机器人自动加入飞书视频会议 |
| 腾讯云实时 ASR | 已实现可配置 Provider | 单麦克风话者识别仍允许人工纠正 |
| Pipecat | 已接入音频输入帧桥 | 不是完整 Pipecat 流水线或媒体服务器 |
| 大模型 | 已实现 OpenAI 兼容接口与 Mock 模式 | 生产效果依赖模型、网络和配置评测 |
| 北森 | 已实现 CSV/XLSX 历史样本预览与脱敏导入 | 未接北森在线 API |
| Obsidian | 已实现审批后发布和系统文档同步 | 不发布候选人原始材料 |
| 数据库 | SQLite 与 PostgreSQL URL 均可配置 | 默认 SQLite 只适合本地或单机试点 |
| 录音 | 本地 WAV 存储和权限下载已实现 | 正式生产仍需对象存储、加密和备份 |

## 成功标准

- 面试官能更快找到值得核实的岗位证据；
- 同一岗位的候选人使用可解释、相对一致的标准；
- AI 建议可以追溯到问题、逐字稿和能力维度；
- 漏问信息与候选人负面表现被明确区分；
- HR 能看见候选人评分，也能复盘面试过程质量；
- 人工始终保留最终招聘决策权。
