# 面后候选人分析：独立于参考问题

左侧问题是可选提问参考，右侧负责实时追问；新建面试继续使用智能混合模式。面后统一根据实际问答分析，不要求点选或问完参考题。

## 报告

- 默认展示本轮建议、简洁理由、岗位匹配分、回答质量分和分析覆盖。
- “展开岗位匹配分析”按核心工作匹配、亲自履职与判断、经验迁移与上手条件、关键差距与用人建议综合分析。每项串起岗位需要、实际表现及其用人含义，不按对话批次展示。
- 评分标准和候选人原话分别二次折叠。分批分析仍保存在报告数据中供追溯，不作为主阅读内容。
- 分数区间依次为 [0,1) 明显不符合、[1,2) 低于要求、[2,3) 部分符合、[3,4) 达到要求、[4,5] 较强匹配。
- 采用 `job-readiness-strict-v1` 履职标准：3分以上须有独立完成主要职责的事实；4分以上还须体现关键机制、取舍与边界。不按工作年限、头衔或表达流畅加分，不用团队成绩替代个人贡献。执行岗与管理岗以实际JD区分，明确的实习/培养岗接受项目证据，不硬套资深经验要求。
- 多批分析成功综合后，采用总体岗位匹配评分，不机械平均局部片段分数。综合失败时保留原观察并明确展示降级说明。
- 没问到、无法核实和模型故障不计零分。通过方向由岗位事实与模型综合判断产生，不按平均分自动淘汰，不改变候选人阶段。
- 对话有可引用观察、但不足以打分时，仍保留具体文字分析，数值显示未评分。

## 故障隔离

能力维度分析或中间汇总失败，不再阻止候选人对话分析。模型全部失败时，不把本地规则分数显示为 AI 岗位匹配结论。

面后模型请求对超时、连接错误、格式错误或输出截断最多重试一次；鉴权或余额错误不重试。区分连接失败、响应超时、输出未完成。DeepSeek Chat 请求直接使用其 JSON Output 格式，保留现有输入长度限制。

多批观察在长度预算内进行综合总结；若总结失败或超预算，保留全部已完成的分批分析，不丢弃成功部分。跨段评价仍沿用已有受限分批与原话复核方式。

## 实时追问表达

模型分别输出 `answer_summary`（忠实概括）、`question`（一个关键追问）、`basis_quote`（逐字原话）。展示为“我理解你的意思是：概括。追问”，原话另存核对；不再自动把原话拼到问题前面。概括不得补写数字、责任归属、因果或能力标签；原话及片段ID仍须通过验证。概括并非语义正确性的证明，面试官应核对；单纯换词不会导致当前卡片跳动。

## 验证与限制

- 单元测试覆盖固定题未问、辅助链路失败、全部失败、无法评分但有具体分析、综合建议、有限重试和报告展开内容。
- 真实 DeepSeek 联调只使用虚构面试，不读取或发送历史候选人资料。
- 2026-09-30 虚构同岗位样例验证：明确不会且不愿亲自动手的回答为0分/不通过；具体部署与排障回答为3.8分/补充验证；仅请求介绍岗位的回答为未评分/补充验证。每例仅一问一答，不代表完整面试效果或已验证招聘效度；相同样例的模型分值和倾向可能波动。
- 模型文字和分数是辅助判断，不保证客观或正确，仍须面试官核对。
- 旧报告刷新页面只能更新展示；获得新的模型分析需点击“重新生成 AI 评价”，不会自动重写已保存报告。
