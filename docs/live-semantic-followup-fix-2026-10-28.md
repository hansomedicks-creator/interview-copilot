# 实时追问模板与降级状态修复

## 已确认的问题

- 生产语义分析的去重分支直接返回规则建议；模型失败分支也返回规则建议。
- 规则问题选择固定序号，反复出现“其中最关键的一步是怎么运作的”。
- 快速字幕更新/读取实时状态会显示 ready，不能证明之前的模型错误已经恢复。
- 降级时将最新回答传入规则 Provider，会产生未经语义核验的关键词证据。
- 追问引用校验原先允许引用最近窗口内其他问题的回答，不强制绑定当前问答。

## 本次改变

- 生产实时追问仅接受通过引用校验的模型建议；等待、去重、失败分支不再输出规则模板。
- 原有规则卡片仍保留在数据库中供审计，但不在生产追问面板重新展示。不删除面试数据。
- 通过历史机制保留同一当前问题的有效建议，切换问题不将旧建议作为当前追问；已跳过的建议不会自动重开。
- 模型提示要求先概括理解、再点出具体疑点；拒绝已知通用模板，校验当前问题与当前回答片段。没有有价值的追问允许返回空数组。
- 去除临场问题上下文中的通用“本人行动、结果”默认追问。
- 降级不新增关键词证据。原有覆盖导航、历史证据和人工流程保持不变。
- 保存最近一次语义请求的状态、错误码、时间、耗时、连续失败数、问题 ID 和逐字稿数量；本地刷新不再覆盖失败状态。
- 同步写出脱敏诊断日志，不记录提示词、逐字稿、候选人姓名、密钥或上游原始错误正文。
- 页面直接显示失败原因，追问区解释等待/失败状态；不声称请求正在自动重试，后续回答触发下一次分析。
- 修正同一成功分析后的页面刷新状态，不显示不存在的新分析任务。
